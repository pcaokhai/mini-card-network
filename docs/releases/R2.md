# R2 — Sprint 2: "The acquirer link to the issuer connects, signs on, echoes, survives a drop, and the ops console shows it live"

Version 1.0 · 2026-09-22 · Sprint 2 (E2 — Network management), per `docs/07-delivery-plan.md` §2–3

Sprint goal achieved: the issuer accepts ISO 8583 connections and answers sign-on/sign-off/echo; the gateway maintains that link (connect, sign on, echo every 60s, detect failure, reconnect with backoff), multiplexes requests/responses safely under concurrency, exposes the link's state and manual controls over REST, and pushes live status/events to a WebSocket hub; the web console's Network Operations screen shows all of it. This release still ships no card-authorization logic — the gateway rejects every financial request with RC 91 (no link is signed on for financial traffic in this sprint's scope) and MCN-302 is where real authorization starts.

## How to test

### 1. Issuer ISO server (no gateway needed — raw socket)

```bash
cd issuer-jpos && ./gradlew spotlessCheck build   # AcquirerLinkRepositoryTest, NetworkManagementIntegrationTest
```

`NetworkManagementIntegrationTest` opens a real TCP socket against a real `ISOServer`/`NACChannel`/`GenericPackager` and a real Testcontainers Postgres, and proves: sign-on updates `acquirer_link` and returns 0810 RC00, echo returns RC00, an unsupported DE70 code returns RC30, a financial request (0200) returns 0210 RC91, and a frame with an unreadable MTI gets the connection closed with no response at all.

### 2. Gateway connection manager (in-process fake issuer — no infra needed)

```bash
cd gateway-go && CGO_ENABLED=0 go test ./internal/isonet/... -v
```

`TestSupervisor_connectsSignsOnAndEchoes`/`TestSupervisor_marksDownAfterThreeFailedEchoes` run against an in-process fake issuer speaking the real framed protocol — confirms sign-on, periodic echo, and DOWN-detection-after-3-failures without needing the real issuer or Docker.

### 3. MUX concurrency proof

```bash
cd gateway-go && CGO_ENABLED=0 go test ./internal/isonet/... -run TestMux -v
# real -race proof needs CI's Linux runner (this dev Mac's Xcode SDK breaks cgo/-race, same known issue as every prior sprint)
```

`TestMux_handles1000ConcurrentRequests` fires 1000 goroutines at one connection concurrently and asserts every one gets its correctly-correlated response — this is what "safe under load" means for MCN-203-AC4.

### 4. Network REST API (gateway only, in-memory link state)

```bash
cd gateway-go && go run ./cmd/gateway
# in another shell:
curl -s localhost:8080/v1/network/links | python3 -m json.tool
curl -s -X POST localhost:8080/v1/network/links/issuer/echo | python3 -m json.tool
curl -s localhost:8080/v1/network/events | python3 -m json.tool
```

Note the real route shape settled on `/v1/network/links` and `/v1/network/links/{linkId}/...` (path param `linkId`) — MCN-204 read the real `contracts/openapi.yaml` before implementing, same as MCN-205 did independently on the frontend side, so the two already agree on the wire without needing a fixup PR.

### 5. Network Operations screen (web console, mock mode)

```bash
cd web-next && NEXT_PUBLIC_API_MOCKS=true pnpm dev
```

Open `http://localhost:3000/network` and check: the link status pill renders with a semantic color per state, the links table shows last-echo/p99/in-flight, the event timeline is severity-color-coded newest-first, and clicking "Echo now" / "Sign on" / "Sign off" calls the (auto-mocked) endpoint with optimistic pill updates on sign-on/sign-off.

### 6. Integration checkpoint (real issuer + real gateway, not mocks)

```bash
make up   # real issuer, real gateway, real Postgres, real Toxiproxy
# in web-next: NEXT_PUBLIC_API_MOCKS=false pnpm dev
```

Open `/network` and confirm the real link signs on within a few seconds, "Echo now" updates the timeline live (polled every 5s this sprint — see Known gaps), and stopping/restarting the issuer container shows the pill go DOWN then recover.

### 7. Per-lane commands (also run in CI, per changed path)


## Known gaps fixed while building this (worth knowing before Sprint 3)

- **jPOS 3.0.1 already ships a working `ISOServer`/`QServer`/`NACChannel` stack** that does everything the MCN-201 plan's hand-rolled socket server would have — including closing the connection on an unpack failure, which is exactly AC4's requirement. Verified against the real 3.0.1 sources jar rather than assuming; using it directly cut the planned file count roughly in half.
- **No `internal/ws.Hub` existed before MCN-204** — the plan assumed MCN-005-GW had already built one; it hadn't. Built from scratch this sprint (new dependency: `gorilla/websocket`), mounted at `/v1/stream`, emitting envelopes matching `contracts/ws-events.schema.json` exactly.
- **`iso8583.Unpack` takes a `string`, not `[]byte`** — MCN-203's `Mux` draft called it with the raw `[]byte` from `ReadFrame`; fixed at all three call sites.
- **`Mux.Send` could block past its own deadline** if the connection's write side never drained, because `WriteFrame` has no cancellation — writing on its own goroutine and selecting against `ctx.Done()` fixed it; caught by a test that hung past its own timeout with a goroutine dump pointing at the blocked write.
- **Shutdown sign-off needs a fresh, non-cancelled context** — once `signOff` started going through `Mux.Send(ctx, ...)`, passing the already-cancelled shutdown `ctx` made it return immediately without ever sending the frame; fixed with a short-lived `context.WithTimeout(context.Background(), ...)` detached from the run context.
- **A genuine `-race`-caught bug**: a test fake (`fakeLinkStore`) was written by the Supervisor's goroutine and read by a polling assertion goroutine with no synchronization — fixed with a mutex, and it's exactly the kind of bug this project runs `-race` on CI to catch.
- **A Testcontainers Postgres readiness race**: `Migrate()` connected immediately after the container reported ready but wasn't yet accepting connections — fixed with a bounded ping-retry, which also protects the real `docker-compose` Postgres at gateway startup, not just tests.
- **`go mod tidy` silently bumped `go.mod`'s `go` directive to 1.26**, which the CI-pinned `golangci-lint` binary (built against 1.25) then refused to lint — fixed by pinning `goose`/`testcontainers-go` to versions that don't require 1.26, rather than touching CI config (a PLAT-lane concern).
- **Real route-shape divergence caught by contract-first development working as intended**: MCN-204's plan draft guessed `/v1/links/{endpoint}/...`; the real `contracts/openapi.yaml` (already used correctly by MCN-205's independently-built frontend) is `/v1/network/links/{linkId}/...`. Both sides read the real contract before finalizing, so gateway and console agree on the wire without a follow-up fixup PR — this is what contract-first is supposed to prevent, and it worked.
- **No `QueryClientProvider` existed anywhere in the web app** before MCN-205 — MCN-104's `useDecodeMessage` mutation only ever worked inside tests (each of which wraps its own `QueryClient`); it would have thrown in the real running app. Fixed with a single shared `QueryProvider` in the root layout.
- **No `useWsEvents` hook exists yet** — MCN-205 ships polling the REST endpoints every 5s instead of consuming MCN-204's new WS broadcasts live. This is a real, tracked gap: the hub emits the right payloads now, but nothing on the WEB side consumes them yet. Whoever builds that hook next can wire it in as a drop-in replacement for the polling.
- **Environment-only gap, not a code bug**: `TestSupervisor_recoversFromToxiproxyLinkDrop` (MCN-202 AC4) needs the real `make up` stack's issuer to speak ISO 8583 over TCP; in the sandbox environments the stories were built in, that container only exposed HTTP admin ports. Confirmed by diffing against `main` with the story's changes stashed — the failure is pre-existing/environmental, not introduced by any Sprint 2 PR. Should now resolve for real since MCN-201 (merged the same day) gives the issuer a real ISO 8583 listener — worth re-running against the full `make up` stack as a Sprint 3 sanity check.
- **Local-machine-only**: `-race` and Testcontainers-backed tests can't run natively on this dev Mac (broken Xcode CommandLineTools SDK for cgo-linked builds, same documented limitation as every prior sprint) — verified functionally with `CGO_ENABLED=0` locally, proven for real on CI's Linux runners.
