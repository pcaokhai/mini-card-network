# R5.1 — The Overview on real data, and reversals that actually complete

Version 1.0 · 2026-09-25 · Patch release on R5 (no new sprint stories; fixes found by the MCN-002 acquirer seed)

**Goal:** after `make up && make seed`, the real stack holds data that makes the Overview page look like the design canvas (Easy and Expert modes), through real traffic only, with no ledger bypass (root CLAUDE.md §9).

**What happened:** building that seed was the first time the whole stack carried real purchases and real reversals end to end, and it showed that neither worked on a fresh stack:
- every purchase declined RC 96;
- no 0420 reversal had ever completed (root CLAUDE.md §6.4, "unknown outcome ⇒ reversal");
- RRNs repeated after a gateway restart;
- the first seed hung on sign-on.

All of these are fixed below, each with a regression test. An independent code-reviewer pass covered every security-sensitive change (key material, reversal, ledger); its blocker and should-fix findings are fixed too.

**Status: final.** Verified on a fresh stack (`make down -v && make up && make seed`, first try):
- **Seed run:** 246 purchases (231 approved; RC 51 ×7, 61 ×4, 62 ×2, 54 ×2), and 2 cancellations that reach `REVERSED`.
- **Consistency:** gateway and issuer agree (229 `APPROVED` / 15 `DECLINED` / 2 `REVERSED`). RRNs are unique, `saf_queue` is fully `ACKED`, `reversal_without_original` = 0, and every issuer journal nets to zero.
- **Cancel guard:** a second cancellation of the same transaction returns 409.

## What was fixed

Each entry covers the symptom, the root cause, the fix, and the test that now guards it.

### Issuer (ISS)

1. **Every real purchase declined RC 96.**
   - **Cause:** `Respond` never MACed the 0210, so the gateway's response-MAC check failed every time.
   - **Fix:** responses are MACed in `signedResponse()`.
   - **Test:** `RespondTest`.
2. **An RC 62 decline crashed with a foreign-key violation.**
   - **Cause:** RCs 06, 10, 17, 62, 68 and 95 were missing from the issuer's response-code table.
   - **Fix:** migration `V6__missing_response_codes.sql`.
   - **Test:** `SchemaMigrationTest`.
3. **Every 0420 was answered RC 30.**
   - **Cause:** `NetworkManagementListener` sits first in `30_iso_server.xml` and answered every MTI class it didn't handle, 04 included, so `ReversalListener` never saw a reversal.
   - **Fix:** it returns `null` for class 04.
   - **Test:** `HandleNetworkManagementRoutingTest`.
4. **A spec-compliant DE 90 never matched its original.**
   - **Cause:** `ParseReversal` trimmed spaces but not the zero fill that docs/03 §7.3 specifies for the acquirer ID (`00000970499`).
   - **Fix:** the zero fill is stripped.
   - **Test:** `ParseReversalTest`.
5. **The 0430 echoed the reversal reason in DE 39.**
   - **Fix:** DE 39 is now the acknowledgement: "00" once the reversal is recorded.
   - **Test:** `RespondReversalTest`.
6. **"00" was sent even when the reversal failed** (review blocker).
   - **Cause:** `RespondReversal.abort()` also answered "00". After a DB error or a missing card, the acquirer marked the transaction `REVERSED` while the issuer never returned the money.
   - **Fix:** an aborted reversal answers "96", and the acquirer's SAF repeats it.
   - **Test:** `abort_answers96SoTheAcquirerRepeats__MCN_401`.
7. **A 0420 that overtook its own 0200 was silently dropped.**
   - **Cause:** if the original was still `RECEIVED`, the reversal was a no-op answered "00". The 0200 then approved and was never reversed.
   - **Fix:** the reversal aborts ("96") so it is repeated after the 0200 settles.
   - **Test:** `prepare_originalStillInFlight_failsSoTheAcquirerRepeats__MCN_401`.
8. **A 0420 and its 0421 in flight together could both return the money.**
   - **Cause:** nothing locked the original, and `markReversed` ran outside the journal transaction.
   - **Fix:** a guarded `APPROVED → REVERSED` update runs first, on the journal's connection. Only the winner posts.
   - **Test:** `prepare_concurrentReversalAlreadyFlippedTheRow_postsNoJournal__MCN_401`, plus `ReversalInterleavingPropertyTest`.

### Gateway: reversal and SAF (GW)

The full defect table and rulings are in `docs/plans/MCN-401-reversal-0420-fix.md`.

9. **The 0420 could not be sent or matched.**
   - **Causes:**
     - DE 90 had a blank STAN, because `tran_log` reads never selected `network_stan`, and "must be numeric" failed the pack.
     - DE 90's DE 7 came from `created_at` instead of what was actually sent.
     - The advice carried only 7 fields, with no DE 2, 3, 7, 11, 12, 13, 15, 22, 25, 32 and no MAC, so the MUX key was empty and no 0430 could ever match.
   - **Fix:** `saf/advice.go` builds the golden-vector field set from what the purchase actually sent (`sent_at`, `processing_code`, `pos_entry_mode`, migration 00006).
   - **PCI:** the PAN is resolved from `card_token` only while building the frame. It is never stored.
   - **Repeats:** STAN and DE 7 are assigned on the first attempt and persisted, so every 0421 repeat is the same message.
   - **MAC:** DE 128 is computed per send.
   - **Tests:** `TestReversalAdvice_*`, `TestWorker_assignsStanOnceAndRepeatsTheSameMessage__MCN_401`, `TestWorker_macsEverySend__MCN_401`, `TestWorker_neverPersistsThePAN__MCN_401`.
10. **Send failures were invisible.**
    - **Cause:** attempts rose while `last_error` stayed null.
    - **Fix:** every failed delivery records why.
    - **Test:** `TestWorker_recordsWhyADeliveryFailed__MCN_401`.
11. **Any 0430 counted as delivered.**
    - **Fix:** only DE 39 = "00" completes the advice.
    - **Test:** `TestWorker_onlyAn00AcknowledgementCompletesTheAdvice__MCN_401`.
12. **Reversals stayed `REVERSAL_PENDING` forever.**
    - **Fix:** `MarkAcked` moves `REVERSAL_PENDING → REVERSED` and writes a history row, in one transaction.
    - **Test:** the `store/safqueue_test.go` MarkAcked tests.
13. **One lost 0430 froze the SAF worker until shutdown** (review).
    - **Fix:** each send times out after 30 s, the same wait as a purchase's 0210 (docs/03 §9).
14. **One DB error shut down the whole gateway** (review).
    - **Cause:** the worker returned store errors out of its errgroup.
    - **Fix:** store errors are logged, and the worker moves on to the next row.
    - **Claim lease:** `ClaimDue` leases rows for 60 s.
    - **Repeat MTI:** an advice that already has a STAN always goes out as 0421, even if its ACK write failed.
    - **Logging:** the worker logs through the gateway's JSON logger.
15. **A link outage could dead-letter a reversal that was still owed** (review).
    - **Cause:** link-down counted as an attempt.
    - **Fix:** no STAN available, a send refused as not signed on, or an issuer RC 91 all wait without counting an attempt, including for 0421 repeats.
    - **Test:** `TestWorker_notSignedOnNeverCountsAsAnAttempt__MCN_401`.
16. **Cancel accepted anything** (review).
    - **Cause:** cancelling a `REVERSED` or `REVERSAL_PENDING` transaction queued a second 0420 and moved `REVERSED` back to pending. A link-down decline or a pre-auth could also be "cancelled".
    - **Fix:** only an `APPROVED` `PURCHASE` can be cancelled, and `Queue` compares and sets the state. Anything else returns 409 `not-reversible`.
    - **Tests:** `TestCancelPurchase_onlyAnApprovedPurchaseCanBeCancelled__MCN_401`, `TestCancelPurchase_refusesAnApprovedNonPurchase__MCN_401`.

### Gateway: network, keys, data (GW)

17. **Duplicate RRNs.**
    - **Symptom:** a second seed run produced 492 rows with only 250 distinct RRNs.
    - **Cause:** every new `Mux` restarted its STAN at 1, on every reconnect and every restart.
    - **Fix:** one STAN counter is shared across the supervisor's connections, and at startup it resumes from the highest STAN in the current RRN hour (`LastSTANInRRNPrefix`). That query ignores any RRN that isn't 12 digits, so a stray row can't block startup.
    - **Test:** `TestSupervisor_resumesAfterTheLastUsedSTAN__MCN_203`, `TestSupervisor_neverMovesTheSTANBackwards__MCN_203`, `TestTranLogRepository_lastSTANInTheHoursRRNPrefix__MCN_203`.
18. **The first seed on a fresh stack failed with `409 broken pipe`.**
    - **Cause:** sign-on waited on the run context with no timeout, and a dead connection was only noticed after sign-on returned.
    - **Fix:** sign-on uses a connection-scoped context, bounded by `EchoTimeout`.
    - **Test:** `TestSupervisor_reconnectsWhenTheConnectionDiesDuringSignOn__MCN_202`.
19. **A fresh stack could not MAC.**
    - **Cause:** `key_store` stayed empty until the first rotation.
    - **Fix:** `ZAK_HEX`/`ZPK_HEX` are registered as `ACTIVE` when none exists. Only the cryptogram and KCV are stored (uppercase, like rotation's), and a key set by a rotation is never overwritten.
    - **Review fixes:** a provisioning failure now stops startup (§6.11), and a configured key whose KCV differs from the `ACTIVE` one is logged with both KCVs.
    - **Tests:** `TestProvisionInitialKey_*`, the `KeyStoreRepository` `EnsureActive` and `ActiveKCV` tests.
20. **Every purchase went to one merchant**, `Ca phe Goc Pho`.
    - **Cause:** the merchant was hard-coded.
    - **Fix:** the merchant is resolved from the terminal. DE 42 and the feed's merchant name come from it. An unknown terminal returns 422 `unknown-terminal`, and an unknown RRN returns 404 `unknown-transaction`.
21. **The Overview couldn't be drawn from real data.**
    - **Cause:** throughput was 1-minute, sparse buckets over 30 minutes.
    - **Fix:** 24 dense 150 s buckets, plus `p50LatencyMs` and `transactionsDeltaPct`.

### Web console (WEB)

22. **Full test PANs were in web source.** The MSW feed embedded full PANs, which breaks root CLAUDE.md §6.2 even for test cards; it now uses last-4 only. The POS card picker lists all six fixture cards.
23. **Flat chart.** At real volume (< 1 TPS per bucket), `max(1, peak)` flattened every bar. Bars now scale to the busiest bucket.
24. **Raw float TPS.** TPS now shows as `vi-VN` with at most 2 decimals.
25. **Overflow at 1280px.** In Expert mode the feed's fixed columns (664px) didn't fit beside the 380px right column, and badges spilled under it. The page uses two columns from 1400px up and stacks below that.
26. **a11y failure.** The KPI sub-lines were `<p>` inside a `<dl>`, which fails axe's `definition-list` rule; they are now `<dd>`.

### Tooling (PLAT)

27. **`scripts/land-pr.sh` raced GitHub three ways** when landing two PRs back to back:
    - A stale `mergeStateStatus` skipped a needed rebase.
    - The worktree was removed before a merge that GitHub then refused.
    - Right after the rebase push, zero pending checks made the merge run before CI had started.

    It now polls the merge state, waits for the run of the pushed SHA, and merges before any cleanup.

## New: `make seed` (gateway)

`gateway-go/internal/seed` does the following, using real API calls only:
1. Upserts the fixture merchants and terminals.
2. Signs the issuer link on.
3. Sets ••••1208's per-transaction limit through the issuer Card Admin API (with `If-Match`).
4. Sends 246 purchases: 96 in the last hour following the canvas's bar heights, 34 earlier today, and 116 in yesterday's window (≈ +12 %).
5. Cancels 2 approvals and waits for `REVERSED`.
6. Backdates the gateway's rows, shifted by how long the run took.

Declines come from real issuer decisions on the fixture cards:

| RC | Card | Why |
| --- | --- | --- |
| 51 | ••••9021 | low balance |
| 61 | ••••1208 | over the limit |
| 62 | ••••3310 | blocked |
| 54 | ••••7765 | expired |

After 5 straight mismatches the run stops early, pointing at link or key trouble.

## How to test

```bash
make down ARGS=-v && make up && make seed
# expect: seeded 246 transactions ... map[51:7 54:2 61:4 62:2 APPROVED:231], 2 reversed

docker exec mini-card-network-postgres-1 psql -At -U acquirer -d acquirer \
  -c "select state, count(*) from tran_log group by 1" \
  -c "select count(*) = count(distinct rrn) from tran_log"
docker exec mini-card-network-postgres-1 psql -At -U issuer -d issuer \
  -c "select count(*) from (select journal_id from ledger_posting group by 1
      having sum(case direction when 'D' then amount else -amount end) <> 0) x"   # expect 0
```

Then open the console (`cd web-next && pnpm dev`) at 1440px and 1280px, in Easy and Expert modes.

Per lane:
- `cd gateway-go && CGO_ENABLED=0 go test -count=1 ./...`
- `cd issuer-jpos && ./gradlew spotlessCheck test`
- `cd web-next && pnpm lint && pnpm test`

## Still open

- **G1:** `GET /v1/network/switch` returns 404 (MCN-802).
- **G3:** `transaction.updated` is never broadcast, so a completed reversal shows only after the next poll.
- **G5:** the decline tail isn't grouped into "Lý do khác".
- **G7:** "today" is the UTC day. This needs a product ruling: business date or local calendar day.
- **R-12:** the gateway never forwards a PIN block, so RC 55 ("Sai mã PIN") can't be produced.
- **Reversed rows show RC 00.** A `REVERSED` row shows its original approval's RC. Showing the 0420 reason needs a new `TransactionSummary` field, which is a contract PR.
- **Review nits not fixed:**
  - A 50-row SAF batch on a half-dead link can hold the worker for up to about 25 minutes.
  - If idempotency storage fails after a cancellation is queued, a retry with the same key gets 409 instead of 202.
  - Completion doesn't check that the looked-up RRN is a pre-auth.
  - A dead-lettered 0420 leaves its transaction `REVERSAL_PENDING`, visible only through the SAF dead metric.
  - The issuer's `ParseReversal` zero-strip would break an acquirer ID that really starts with 0.
  - The 0430 carries no MAC, and the issuer doesn't verify the 0420's DE 128.
- **Lint versions differ.** CI pins golangci-lint v2.6.1, which reports differently from newer local versions. The CI job is the gate.
