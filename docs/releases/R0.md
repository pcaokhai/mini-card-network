# R0 — Sprint 0: "Everyone can build, run and see traces"

Version 1.0 · 2026-09-22 · Sprint 0, per `docs/07-delivery-plan.md` §3

Sprint goal achieved: every lane has a working scaffold, `make up` starts the whole
platform, and a request to any of the three backend skeletons produces a real trace in
Tempo. No business logic ships in this release — that starts in Sprint 1 (E1, message
codec and Message Lab).

## How to test

### 1. One-time setup

```bash
git clone <repo> && cd mini-card-network
cp .env.example .env   # created automatically by `make up` if you skip this
```

If port `5432` is already used by another Postgres on your machine, set
`POSTGRES_HOST_PORT` in `.env` to a free port first (see `infra/README.md`).

### 2. Bring up the whole platform

```bash
make up
```

Expect it to finish in well under 90 s (warm) and print `post-up: kafka topics ready`.
It starts, in one Docker network:

| Service | Port(s) | What to check |
| --- | --- | --- |
| postgres | `${POSTGRES_HOST_PORT:-5432}` | `docker compose ... exec postgres psql -U postgres -l` shows `issuer`, `acquirer`, `settlement` |
| kafka | 9092 | topics `issuer.transactions.v1`, `acquirer.transactions.v1` exist |
| toxiproxy | 8474 (admin), 18000 (proxy) | `curl localhost:8474/proxies` lists `issuer` |
| otel-collector | 4317/4318 (OTLP), 13133 (health) | `curl localhost:13133/` returns 200 |
| tempo | 3200 | `curl localhost:3200/ready` |
| prometheus | 9090 | `curl localhost:9090/-/ready` |
| grafana | 3001 | open `http://localhost:3001`, anonymous viewer access |
| gateway | 8080 (API), 9464 (metrics) | see below |
| issuer | 8081 (health/admin), 9465 (metrics) | see below |
| settlement | 8082 (API), 9466 (management) | see below |

Tear down with `make down` (keeps volumes) or `make down ARGS=-v` (wipes everything).

### 3. Verify each of the three service skeletons the same way

Every one of gateway/issuer/settlement exposes the same shape, so the check is
identical — only the port and `service.name` change.

```bash
# health
curl -fsS http://localhost:8080/health/live    # gateway
curl -fsS http://localhost:8080/health/ready
curl -fsS http://localhost:8081/health/live    # issuer
curl -fsS http://localhost:8081/health/ready
curl -fsS http://localhost:8082/health/live    # settlement (management port is 9466, not 8082)
curl -fsS http://localhost:9466/health/ready

# metrics (Prometheus text format)
curl -fsS http://localhost:9464/metrics | grep go_goroutines     # gateway
curl -fsS http://localhost:9465/metrics | grep jvm_memory        # issuer
curl -fsS http://localhost:9466/prometheus | grep jvm_memory     # settlement

# a trace (W3C traceparent), then look it up in Tempo
TRACE=$(openssl rand -hex 16)
curl -fsS -H "traceparent: 00-${TRACE}-$(openssl rand -hex 8)-01" http://localhost:8080/health/ready
sleep 5
curl -fsS "http://localhost:3200/api/traces/${TRACE}" | grep -q gateway && echo trace-in-tempo

# JSON logs with PAN masking (send a card number through any of the three logs and
# confirm the raw PAN never appears — masking is unit-tested per service, this just
# spot-checks the live container)
docker compose --project-directory . -f infra/docker-compose.yml -f gateway-go/compose.yaml logs gateway | tail -5
```

### 4. Graceful shutdown (NFR-09)

```bash
docker compose --project-directory . -f infra/docker-compose.yml -f gateway-go/compose.yaml stop gateway
# expect: exits well under the 35s grace period; logs show "draining" then "gateway stopped"
```

Same pattern for `issuer-jpos/compose.yaml` (look for `Commencing graceful shutdown` /
`Graceful shutdown complete`) and `settlement/compose.yaml` (Spring Boot's own
`GracefulShutdown` log lines).

### 5. Per-lane commands (no Docker needed)

Each of these also runs in CI, per changed path, on every PR.

```bash
make -C web-next lint test        # Next.js: eslint, tsc, generated-code freshness, 8 vitest cases
(cd web-next && pnpm test:stories && pnpm exec storybook build)  # story tests + Storybook (local only, not in CI)

make -C settlement lint test      # Spotless + JUnit/ArchUnit
make -C issuer-jpos lint test     # Spotless + JUnit/ArchUnit

make -C gateway-go lint test      # gofmt + golangci-lint v2 + go test -race

make contracts                    # Spectral, oasdiff, ISO vectors, JSON Schemas (see below)
```

`make contracts` runs, in order: `deps` (pip install), `lint` (Spectral against
`contracts/.spectral.yaml`), `ruleset-selftest` (the 4 custom rules must reject
`contracts/scripts/testdata/bad-openapi.yaml`), `vectors` (4 golden + 5 invalid ISO 8583
vectors round-tripped through `contracts/scripts/mcn87a.py`), `schemas` (WS + Kafka JSON
Schema validation), `unit` (7 pytest cases for the reference codec), `breaking` (oasdiff
against `origin/main`, skipped if the PR carries the `api-breaking` label).

### 6. Whole-repo checks

```bash
make lint test     # everything above, scaffolded services only — skips cleanly otherwise
```

## Known gaps fixed while building this (worth knowing before Sprint 1)

These were real bugs found during implementation, not design choices — see the merged
PRs' descriptions for the full root-cause writeups:

- **Spring Boot 4** disables metrics export under `@SpringBootTest` by default; needs
  `@AutoConfigureMetrics` (package moved to
  `org.springframework.boot.micrometer.metrics.test.autoconfigure`).
- **logstash-logback-encoder 9.0** changed its masking config shape: use
  `<decorator class="...MaskingJsonGeneratorDecorator">` directly under `<encoder>`, not
  `<jsonGeneratorDecorator class="...">`.
- **Javalin 7** removed `.get()`/`.post()` from the `Javalin` instance; register routes
  via `config.routes.get(...)` inside `Javalin.create(config -> ...)`.
- **jPOS 3.0.1** deploy-descriptor env-var-with-default syntax is `${NAME:default}`, not
  `${env:NAME:default}`.
- Root `Makefile`'s `up`/`down` now discover every `<service>/compose.yaml` via wildcard
  (a service's compose file was silently ignored before MCN-005).
- CI needs `actions/setup-java` (Gradle lanes) and `actions/setup-go` +
  `golangci-lint-action@v7` pinned to `v2.6.1` (Go lane) — none of this was wired by
  MCN-001 and every Gradle/Go PR's first CI run failed until fixed.
- `gateway-go`'s `go.mod` is pinned to Go 1.24, not the newest local toolchain (1.26):
  no published `golangci-lint` release yet builds with 1.26, so linting a module that
  targets it fails outright.
