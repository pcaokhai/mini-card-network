# R5.3: every console screen as in the design

Version 1.0 · 2026-09-25 · Patch release on R5.2 (screen fidelity), plus MCN-705 (Sprint 8, WEB) against dev:mock

**Why:** after the Overview, POS and Journey (R5.1, R5.2), the user asked for the six remaining screens to match the design canvas. Where the backend lacks a feature, the screen uses `pnpm dev:mock` data. The user also asked whether these pages should already have been finished in the current sprint.

**Answer:** five of the six should have been. The sprint table in `docs/07-delivery-plan.md` puts them in releases that have already shipped:
- Message Lab: MCN-104, Sprint 1, R1
- Network: MCN-205, Sprint 2, R2
- Cards: MCN-309, Sprint 4, R3
- Chaos Lab: MCN-405, Sprint 5, R4
- Security: MCN-505, Sprint 7, R5

They did ship with working features and tests. But each story was checked against its own tests and mocks, never against the canvas, the same gap the Overview, POS and Journey had. Settlement (MCN-705) belongs to the current sprint, Sprint 8, which is planned but had no commits yet. Its backend (MCN-702, MCN-704) is Sprint 9.

**Status: final.** All seven PRs are squash-merged with green CI; `web-next` passes 248 unit tests plus its storybook/axe suites.
- **Visual check:** each screen was compared with its canvas (`project/<Screen>.dc.html`), including the markup, every Easy/Expert string and the keyframes. Screenshots were taken at 1440×1024 and 1280, in Easy and Expert modes, with a mid-animation frame, against dev:mock and the real stack.
- **Orchestrator review:** before merging, the orchestrator reviewed the screenshots and sent three screens back:
  - Network: English event texts on a Vietnamese screen, and an uncapped event log;
  - Cards: a ledger of about 30 rows, making a 1900px page;
  - Chaos Lab: the label "— giao dịch được duyệt" with no run yet.

## Per screen

Each screen records its Rulings in its plan. Below: what changed, and every deliberate difference from the canvas.

### Phòng lab message (MCN-104, #101), plan `docs/plans/MCN-104-lab-canvas.md`

**Built:**
- the sample tabs (0200 Mua hàng / 0210 Trả lời / 0420 Hủy / 0800 Kiểm tra kết nối);
- "Message thô, đúng như gửi trên đường truyền", with coloured segments for MTI, bitmap and fields;
- the bitmap grid (Chính 1–64 / Phụ 65–128) with each byte's hex and binary, and the diagonal flip on a message change;
- the dark field detail card;
- the field table (Easy names, or Expert technical names and formats).

**Rulings:**
- **R1** No paste box, as in the canvas. The screen dissects the gateway's samples through the decode endpoint.
- **R2** Field names and explanations come from a `lab.fields` glossary written in the canvas's voice. DE 15, 43 and 128, which appear in the real samples, got entries; the gateway's names are the fallback.
- **R3** Off bits use #6B6D75 instead of the canvas's #8A8C94, whose 3.2:1 contrast fails axe.
- **R4** "Phụ 65–128" is always shown and disabled while bit 1 is off.
- **R5** A container query narrows the Expert columns below 1440.
- **R6** Tab labels stay on one line.
- **R7** The MTI digits are read from digit glossaries, so a 0810 isn't labelled as acquirer-originated.
- **R8** JetBrains Mono 500 is imported by the screen.

### Vận hành mạng (MCN-205 + MCN-804 parts, #100), plan `docs/plans/MCN-205-network-canvas.md`

**Built:**
- the connection diagram (POS → acquirer → switch → issuer), with links flowing in the request direction, and red, dashed and still when down;
- the links table with "Kiểm tra ngay" (echo);
- "Tự ngắt và duyệt thay" (breaker pills, STIP tiles);
- "Hàng đợi gửi lại";
- "Nhật ký sự kiện hôm nay";
- "Mô phỏng ngân hàng phát hành sập".

**Rulings:**
- **1** The issuer-down toggle drives the real `ISSUER_DOWN` chaos scenario. It was verified in dev:mock only, because on the real stack it cuts the shared issuer link.
- **2** Only the echo button stays in each row. The gateway signs on again by itself (R5.2 §12).
- **3** Addresses show without ports: `Link` carries ids, not host:port.
- **4** The POS node counts "máy đã đăng ký" from `/v1/terminals`. The API has no online flag, so the canvas's "đang trực tuyến" is not shown.
- **5** On the real stack, `/v1/network/switch` returns 404 (MCN-802), so the switch, breaker and STIP parts show "chưa có dữ liệu".
- **6** Motion is on transform/opacity only: the flowing link translates a striped layer.
- **7** Gateway event texts are English. The five known texts map to vi/en copy; unknown text renders as sent, and Expert shows the gateway's technical text. The log shows the 5 newest rows plus "Xem thêm N sự kiện" (max 30). *Fixed after review.*
- **8** The header's amber "Đang duyệt thay…" pill during STIP needs a change to the shared Header. Follow-up.
- **9** The two columns stack below 1400px.
- **10** The inactive breaker pill ink is #5E6068, because the canvas's 4.4:1 fails axe.
- **11** A manual echo on the real gateway doesn't move `lastEchoAt`. Gateway follow-up.
- **12** The chaos scenario mocks the toggle needs live in `pages/network.ts`.

### Thẻ và tài khoản (MCN-309, #102), plan `docs/plans/MCN-309-cards-canvas.md`

**Built:**
- the card list with status badges;
- the card visual;
- "Trạng thái thẻ" with "Khóa thẻ", inline confirmation, the lock overlay animation and the audit line;
- "Số dư" (ledger, holds, available) and the hold note;
- "Hạn mức" sliders with the usage bar;
- "Lịch sử tiền vào, tiền ra";
- a 412 on a limit change reads "Someone changed this card. Reload to continue."

**Rulings:**
- **R1** One screen serves both routes. `/cards` selects the first card; `/cards/[cardRef]` selects that card. List items are links.
- **R2** Cards are sorted by last four digits, as the canvas does; all 6 fixture cards are shown.
- **R3** 7765 shows as expired based on its expiry month; the issuer still reports it ACTIVE.
- **R4** The block reason is `CUSTOMER_REQUEST`, because the canvas has no reason picker.
- **R5** The audit line shows this session's action at the real time, because the issuer has no audit read API.
- **R6** Limits save when a slider is released. An issuer limit of 0 reads "Chưa đặt".
- **R7** Expert ledger legs show `ACC-<cardRef>` as the API returns it (the Journey money panel relies on that prefix). A journal whose description is only generated is named by its entry type.
- **R8** Declines and "báo mất thẻ" render as 0 ₫ "Không hạch toán" rows when the source has them; that happens in dev:mock only.
- **R9** dev:mock values follow the Cards canvas: 4417 has 5 000 000 ₫ ledger, a 1 500 000 ₫ hold and 3 500 000 ₫ available.
  - Side effect: in dev:mock the POS tile for 4417 shows 3 500 000 ₫, and the Journey money panel for 626514000123 reads 5 250 000 → 5 000 000. The Journey and Cards canvases disagree on this balance.
- **R10** The usage bar animates `scaleX`, not `width`. The overlay, confirm and audit timings match the canvas.
- **R11** `.cards-root` restores the browser line-height and range margins, so text sits within 1px of the canvas.
- **R12** At 1280 the Expert legs wrap before the description; there is no horizontal overflow.
- **R13** Only ACTIVE holds are listed.
- **R14** The ledger shows the newest 8 journals. "Xem thêm" (Easy) or "Load more" (Expert) fetches the next page with the issuer's `nextCursor` (`useCardLedgerPages`). *Fixed after review:* card 4417's page went from about 1900px to 1165px.

### Phòng lab sự cố (MCN-405, #103), plan `docs/plans/MCN-405-chaos-canvas.md`

**Built:**
- the six scenario cards (Mạng chậm, Mất kết nối, Mất câu trả lời, Gửi trùng, Ngân hàng phát hành sập, Câu trả lời đến muộn), each highlighted while on;
- "1 sự cố đang bật", "Tắt tất cả" and "Chạy thử 100 giao dịch";
- "Kiểm chứng tiền", with the ledger check that flashes when a run finishes;
- "Hệ thống đang phản ứng thế nào".

**Rulings:**
- **R1** Card copy comes from messages keyed by scenario id (vi/en); the API's single-language text is not shown.
- **R2** Runs are independent 100-transaction runs, and the panel shows the latest one. There is no list-runs endpoint, so before any run the rows show "—" and the badge reads "Chưa chạy thử".
- **R3** The approved row's amount is opening − closing once the run finishes. A FAILED run shows "Sổ sách lệch" and the discrepancy in red.
- **R4** SAF depth and latency come from `/v1/network/saf` and the Overview's p99.
- **R5** The header pill follows the real link, not the chaos toggles.
- **R6** The money flash is an opacity overlay, replayed for each run.
- **R7** "Chạy thử" is disabled while a run is RUNNING or VERIFYING.
- **R8** A failed toggle or run start shows a one-line alert.
- *Fixed after review:* with no run, the label reads "Giao dịch được duyệt" and only the value is "—".

### Bảo mật và khóa (MCN-505, #104), plan `docs/plans/MCN-505-security-canvas.md`

**Built:**
- "Khóa đang sử dụng": KCV, lifetime bar, status and "Xoay khóa ngay";
- "Xoay khóa mã hóa PIN": 4 steps with the KCV flip;
- "Mã PIN được bảo vệ thế nào": a PIN block built row by row, with the XOR reveal;
- "Những điều hệ thống không bao giờ làm".

**Rulings:**
- **1** Keys are the gateway's (`/v1/keys/acquirer`): ZPK and ZAK on the real stack, the canvas's six in dev:mock. `/v1/keys/issuer` is dropped, because nothing serves it through the BFF.
- **2** Rotation follows the rotation resource by polling, not a manual "Bước tiếp". While running the button reads "Đang xoay…".
- **3** Only the ZPK can be rotated from here, as in the canvas.
- **4** The Expert steps show the rotation's real `newKcv`, or `······` until one exists.
- **5** The PIN block uses a made-up card, `9704 36•• •••• 7890`, labelled "Số thẻ minh họa". It is not a fixture card and not Luhn-valid. Before, the visualiser and the canvas used the real fixture card `…4417` in client code.
- **6** The TPK note doesn't invent "42 máy POS".
- **7** Motion is on transform/opacity: the lifetime bar animates `scaleX`.
- **8** The PCI card moves under the other two below 1400px.

### Chốt ngày và đối soát (MCN-705, #105), plan `docs/plans/MCN-705.md` (the "Canvas pass" section)

**Built:** a new screen replacing the `ComingSoon` placeholder:
- four steps from the business day's stage (Khóa sổ, Gửi bảng tổng kết, Đối soát từng giao dịch, Xuất file quyết toán) with the step pop;
- "So nhanh tổng số liệu hai bên" with match badges and a match bar;
- "Các chênh lệch cần xử lý", resolved one by one, each row fading up;
- the dark net-position card;
- "File quyết toán";
- the `409 open-breaks` detail shown inline with a shake (AC2).

It uses a typed `settlement-client.ts` over the contract, with mocks from `createSettlementHandlers(stage)`.

**Rulings:**
- **R1** This sprint builds the screen against MSW. MCN-702/704 are Sprint 9.
- **R2 and R3** Steps follow `SettlementStage`: five stages, four steps.
- **R4** Step 2 has no endpoint, because the 0500 exchange follows the cutover inside the gateway. The button shows "Đang gửi tổng kết…" while the day is polled.
- **R5** There is no "Làm lại từ đầu", because a closed day can't be reopened.
- **R6** Match badges come from `TotalsRow.matches`.
- **R7** Amounts use the day's currency.
- **R8** Resolving a break sends a `resolution` chosen by break type.
- **R9** The 409 detail is shown verbatim.
- **R10** Motion is on transform/opacity.
- **R11** The business date is the viewer's local day.
- **R12** On the real stack, a designed "Chưa có dịch vụ đối soát trên hệ thống này" card replaces an error, with no retry storm.
- **R13** No `FF_S7_SETTLEMENT` check yet, because web-next reads no slice flags.
- **R14** The file layout.

## How to test

```bash
cd web-next && pnpm dev:mock        # every screen with canvas data
cd web-next && pnpm dev             # real stack through the BFF (make up first)
# toggle Dễ hiểu / Chuyên sâu in the header; screens: /lab/message /network /cards /lab/chaos /security /settlement
cd web-next && pnpm lint && npx tsc --noEmit && pnpm test && pnpm build
```

On the shared real stack, avoid:
- the Network screen's "Mô phỏng ngân hàng phát hành sập";
- Chaos Lab runs;
- key rotation.

These change the issuer link or the working keys for everyone using the stack.
