# MCN-205 Network Operations screen — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans with superpowers:test-driven-development. Worktree `../mcn-worktrees/web-205-network-ops`, branch `feat/MCN-205-network-ops`. Requires MCN-004 merged (console shell + MSW). Does **not** wait for MCN-204 (GW) — builds against MSW mocks generated from `contracts/openapi.yaml`'s `/v1/links` and `/v1/network/events` paths, per the delivery plan's "frontend never waits for backend" rule (same pattern as MCN-104/MCN-103 in Sprint 1).

**Goal:** Ops console screen showing link status (topology pill + table), a live event timeline fed by the `link.status`/`network.event` WS events, and manual echo/sign-on/sign-off buttons.

**Architecture:** `web-next/src/app/(console)/network/` — `NetworkScreen.tsx` (container: TanStack Query for `GET /v1/links` + `/v1/network/events`, subscribes to the WS hub via the existing `useWsEvents` hook from MCN-004/MCN-104), `LinkStatusPill.tsx` (header badge, reused across screens), `LinksTable.tsx` (presentational), `EventTimeline.tsx` (presentational, virtualized-free since v1 event volume is tiny — YAGNI on virtualization until proven necessary), `TriggerButtons.tsx` (calls the three POST endpoints via the generated `openapi-fetch` client, optimistic-UI per `rules/web/patterns.md`: snapshot → optimistic pill state → roll back on failure).

**Tech Stack:** Next.js App Router (client component — this screen is interactive/live), Zustand (none needed beyond what MCN-004 already has — server state lives in TanStack Query, no duplicate client store per `rules/web/patterns.md`), TanStack Query, `openapi-fetch`, MSW, Vitest + Testing Library, Storybook, `next-intl`.

**Spec:** `contracts/openapi.yaml` (`/v1/links`, `/v1/network/events`, `/v1/links/{endpoint}/{action}`), `contracts/ws-events.schema.json` (`link.status`, `network.event`), `docs/06-user-stories.md` MCN-205, `rules/web/design-quality.md` (anti-template policy — this is a network topology/ops screen, a natural fit for a Swiss/technical-dashboard direction with real hierarchy, not a generic card grid).

## Rulings

- **Visual direction:** Swiss/technical — monospace for STAN/RRN-adjacent identifiers, a status pill with color-coded semantic states (green SIGNED_ON, amber CONNECTED, red DOWN, gray DISCONNECTED), and a timeline with real typographic hierarchy (timestamp de-emphasized, easyText prominent, technicalText in a secondary monospace line) — satisfies `rules/web/design-quality.md`'s "at least four qualities" bar via: (1) hierarchy through scale contrast, (5) color used semantically for link state, (6) designed hover/focus on trigger buttons, (10) the event timeline treated as a real data-viz component, not a raw list dump.
- **MSW mock data**: add `contracts/fixtures/network.json` fixture (one `Link` in `SIGNED_ON`, 3 sample `NetworkEvent`s spanning INFO/WARN/ERROR) — this is a WEB-owned fixture addition under `contracts/fixtures/`, not a schema change, so it doesn't need a separate contract PR (same precedent as MCN-104's `contracts/fixtures/messages.json`).
- **WS reconnect**: reuses MCN-004's existing `useWsEvents` hook's reconnect-with-backoff behavior unchanged — no new reconnect logic in this story.

```tsx
// EventTimeline.tsx
interface NetworkEvent {
  id: number
  occurredAt: string
  severity: 'INFO' | 'WARN' | 'ERROR'
  easyText: string
  technicalText: string
}

export function EventTimeline({ events }: { events: NetworkEvent[] }) {
  const sorted = [...events].sort((a, b) => b.occurredAt.localeCompare(a.occurredAt))
  return (
    <ul className="event-timeline">
      {sorted.map((event) => (
        <li key={event.id} data-severity={event.severity}>
          <time dateTime={event.occurredAt}>{new Date(event.occurredAt).toLocaleTimeString()}</time>
          <p className="event-easy-text">{event.easyText}</p>
          <p className="event-technical-text">{event.technicalText}</p>
        </li>
      ))}
    </ul>
  )
}
```

```tsx
'use client'
import { useState } from 'react'
import { apiClient } from '@/lib/api-client' // confirm real import path from MCN-004 before use

type Action = 'echo' | 'sign-on' | 'sign-off'

export function TriggerButtons({ endpoint }: { endpoint: string }) {
  const [pending, setPending] = useState<Action | null>(null)

  async function trigger(action: Action) {
    setPending(action)
    try {
      await apiClient.POST('/v1/links/{endpoint}/{action}', { params: { path: { endpoint, action } } })
    } finally {
      setPending(null)
    }
  }

  return (
    <div className="trigger-buttons">
      <button type="button" disabled={pending !== null} onClick={() => trigger('echo')}>Echo now</button>
      <button type="button" disabled={pending !== null} onClick={() => trigger('sign-on')}>Sign on</button>
      <button type="button" disabled={pending !== null} onClick={() => trigger('sign-off')}>Sign off</button>
    </div>
  )
}
```

```tsx
'use client'
import { useQuery } from '@tanstack/react-query'
import { apiClient } from '@/lib/api-client'
import { LinksTable } from '@/components/network/LinksTable'
import { EventTimeline } from '@/components/network/EventTimeline'
import { TriggerButtons } from '@/components/network/TriggerButtons'
import { useWsEvents } from '@/hooks/useWsEvents' // confirm real hook path/signature from MCN-004

export function NetworkScreen() {
  const linksQuery = useQuery({
    queryKey: ['links'],
    queryFn: async () => (await apiClient.GET('/v1/links')).data ?? [],
  })
  const eventsQuery = useQuery({
    queryKey: ['network-events'],
    queryFn: async () => (await apiClient.GET('/v1/network/events')).data ?? [],
  })

  useWsEvents(['link.status', 'network.event'], () => {
    linksQuery.refetch()
    eventsQuery.refetch()
  })

  return (
    <section aria-labelledby="network-heading">
      <h1 id="network-heading">Network Operations</h1>
      <TriggerButtons endpoint="issuer" />
      <LinksTable links={linksQuery.data ?? []} />
      <EventTimeline events={eventsQuery.data ?? []} />
    </section>
  )
}
```
