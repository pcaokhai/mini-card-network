> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans with superpowers:test-driven-development. Worktree `../mcn-worktrees/plat-407`, branch `chore/MCN-407-chaos-suite`. Requires MCN-401, MCN-402 merged (Sprint 5). Lane PLAT: touches `Makefile`, `gateway-go/internal/chaos/` (the `DROP_RESPONSE` fake-issuer simulator only — no other gateway package), and a new `scripts/chaos-report.sh` / CI workflow addition.

**Goal:** `make chaos` runs the real six MCN-404 scenarios at scale (500 tx/scenario on a PR labelled `chaos`, 10,000 tx/scenario nightly) against a real `chaos.Runner`, fails the build on any ledger discrepancy / DEAD SAF item / non-final transaction after drain, and emits a markdown report artifact. It also replaces `DROP_RESPONSE`'s `501` stub (`chaos.ErrScenarioNotImplemented`, `gateway-go/internal/chaos/toxiproxy_client.go:16`) with a real fake-issuer response-dropping simulator.

**Architecture:** A new `scripts/chaos/run.go` CLI (built by `make chaos`, not a test file — chaos runs are not part of `go test`) drives `chaos.Runner.Start` once per scenario via the real `/v1/chaos/scenarios/{id}` and `/v1/chaos/runs` HTTP API (MCN-404, already implemented) against a running `make up` stack, polls `GET /v1/chaos/runs/{runId}` until `PASSED`/`FAILED`, and writes `chaos-report.md`. The `DROP_RESPONSE` gap is closed by a small `internal/chaos/fakeissuer` package: a TCP listener that accepts the gateway's ISO 8583 connection (same framing as the real issuer, `internal/isonet.Framer`) and, when armed, reads the request and never writes a response — reusing the existing "response never arrives" contract the gateway's own 30 s request timeout (`docs/03` §9) already handles via `purchase.Service`'s timeout branch (MCN-401). `chaos.ToxiproxyClient.SetScenario(DROP_RESPONSE, true)` now points the issuer link at this simulator's address instead of the real issuer/Toxiproxy proxy (only for chaos runs; production and the other five scenarios are untouched).

**Tech Stack:** Go 1.24 (CLI + fake-issuer package), bash (`Makefile` target, CI wiring), existing `gateway-go/internal/chaos`, `internal/isonet`.

**Spec:** `docs/06-user-stories.md` MCN-407 (AC1-AC3), `docs/03-iso8583-interface-spec.md` §9 (30 s request timeout — the mechanism DROP_RESPONSE exploits), `docs/releases/R4.md` "Known gaps" (documents this exact dependency and that `DROP_RESPONSE` stubs a `501`), `gateway-go/internal/chaos/runner.go` (`Runner.Start`/`Get`, ledger-discrepancy computation), `gateway-go/internal/chaos/toxiproxy_client.go` (`ErrScenarioNotImplemented`, `specFor`, `AllScenarios`), `Makefile:70-71` (current `chaos:` stub).

## Global Constraints

- No PAN or PIN ever appears in `chaos-report.md` — the report is counts and RCs only, sourced from `ChaosRun`'s existing fields (`gateway-go/internal/chaos/runner.go:60-70`), which already carry no card data.
- Money stays `int64` minor units throughout (`ChaosRun.OpeningBalanceTotal`/`ClosingBalanceTotal`/`LedgerDiscrepancy` are already `int64`; this plan does not change their type).
- `make chaos` must be a real target, not the current `@echo "not implemented until MCN-407"; exit 2` stub (`Makefile:70-71`).
- The fake-issuer simulator lives under `gateway-go/internal/chaos/fakeissuer/` — it is chaos-suite-only test infrastructure, never wired into `cmd/gateway`'s production binary.

## Ruling 1: `DROP_RESPONSE` simulator reuses `internal/isonet.Framer`, doesn't reinvent framing

`gateway-go/internal/isonet/framer.go` already implements the 2-byte-length-prefixed framing the gateway's `Supervisor`/`Mux` use against the real issuer (confirmed by reading `internal/isonet/mux.go` and `framer.go` before writing this plan). The fake-issuer simulator's listener uses the same `Framer.ReadMessage`/`WriteMessage` pair so the gateway's `Supervisor` connects to it exactly as it would to a real jPOS issuer — no protocol-level stub, only the never-respond behavior. This means the simulator only needs to *read* one framed message per connection and hold the connection open (never write, never close) until the gateway's own 30 s timeout fires and reconnects; it needs no ISO 8583 codec at all (it doesn't decode the frame contents).

## Ruling 2: Report format and CI thresholds

`chaos-report.md` is a fixed table — one row per scenario (`SLOW_NETWORK`, `CONNECTION_CUT`, `DROP_RESPONSE`, `DUPLICATE_REQUEST`, `ISSUER_DOWN`, `LATE_RESPONSE`, per `chaos.AllScenarios`) with columns `Requested | Approved | Declined | Reversed | LedgerDiscrepancy | Status`. The suite fails (`os.Exit(1)`) if any row's `LedgerDiscrepancy != 0`, or if `GET /v1/network/saf`'s `deadCount` (already exposed, MCN-401) is non-zero after all scenarios finish, or if any transaction created during the run is still non-final (`Status` not in `{APPROVED, DECLINED, REVERSED}`) after `chaos.Runner`'s own SAF-drain wait (`waitForSafDrain`, `runner.go:172-180`) plus a final `GET /v1/network/saf` poll. Transaction count per scenario: `500` when `CHAOS_TX_PER_SCENARIO` is unset (PR mode) or set to `500`; `10000` when set to `10000` (nightly cron sets it). This is a Ruling, not read off any existing file, because MCN-404's `Runner.Start(ctx, requested)` already takes `requested` as a plain `int` — no existing constant fixes it at 500/10000.

### Task 1: `fakeissuer.Listener` — accepts a connection, never responds

**Files:** `gateway-go/internal/chaos/fakeissuer/listener.go`, test

**Interfaces:** `NewListener(addr string) (*Listener, error)`; `(*Listener) Addr() string`; `(*Listener) Serve(ctx context.Context) error` (accepts connections in a loop, reads exactly one framed message per connection via `isonet.Framer`, then blocks on `ctx.Done()` without writing — simulating "the issuer received the request but its reply never arrives"); `(*Listener) Close() error`.

- [x] **Step 1: Write the failing test**

```go
package fakeissuer

import (
	"context"
	"net"
	"testing"
	"time"

	"github.com/stretchr/testify/require"

	"github.com/mcn/gateway-go/internal/isonet"
)

func TestListener_acceptsAndNeverResponds__MCN_407_AC_DROP(t *testing.T) {
	l, err := NewListener("127.0.0.1:0")
	require.NoError(t, err)
	defer func() { _ = l.Close() }()

	ctx, cancel := context.WithCancel(context.Background())
	defer cancel()
	go func() { _ = l.Serve(ctx) }()

	conn, err := net.DialTimeout("tcp", l.Addr(), time.Second)
	require.NoError(t, err)
	defer func() { _ = conn.Close() }()

	framer := isonet.NewFramer(conn)
	require.NoError(t, framer.WriteMessage([]byte("fake-0200-payload")))

	_ = conn.SetReadDeadline(time.Now().Add(300 * time.Millisecond))
	_, err = framer.ReadMessage()
	require.Error(t, err) // deadline exceeded: nothing was ever written back
}
```

Check: confirm `isonet.NewFramer`'s exact constructor signature (`framer.go`) before writing this test — adjust the call if it takes an `io.ReadWriter` vs separate reader/writer.

## Implementation notes (discovered during execution, not re-litigating the plan)

- `GET /v1/network/saf` (depth/deadCount/items) was fully specified in `contracts/openapi.yaml`
  and `store.SafRepository.ListPending`'s own doc comment already said it backed that route, but
  the HTTP handler had never been added (`internal/api/network.go`). MCN-407-AC2 needs
  `deadCount` over HTTP for the standalone chaos-run CLI, so this plan closes that pre-existing
  gap (new `SafRepository.ListItems`, `MountNetwork`'s optional `SafReader` param) rather than
  inventing a chaos-only side channel for data the contract already describes. No `contracts/`
  file was touched - the schema already existed.
- `scripts/chaos` is its own Go module (repo root has no top-level `go.mod`), so the Makefile
  target `cd`s into it rather than running `go run ./scripts/chaos` from the repo root.
- `gateway-go/compose.yaml` had no `DATABASE_URL` for the `gateway` service (pre-existing since
  MCN-005 - unrelated to MCN-407) - the container crash-looped on `migrate database` against an
  empty DSN before this plan's changes could be verified at all. Added it (points at the
  `acquirer` role/DB `infra/postgres/init/01-init.sh` already creates) so `make up` can start the
  gateway. Flagged to the team lead as a pre-existing gap outside this lane, not a MCN-407 change.
- Full local end-to-end verification (`make up` + `make chaos` against real 0200 traffic) was
  blocked by an unrelated, pre-existing `issuer-jpos` Docker build failure (`generatePackager`
  task can't see `/contracts/iso8583/packager-spec.yaml` - its build context is `./issuer-jpos`
  only, not the repo root) - an ISS-lane issue, out of scope here. Verified instead with gateway +
  postgres + toxiproxy + otel-collector only: confirmed `DisableAll`/live scenario toggling,
  Toxiproxy's `issuer` proxy upstream repointing to `gateway:19999` and back on `DROP_RESPONSE`
  enable/disable, `GET /v1/network/saf`, and the chaos-run CLI's full HTTP loop (enable → start
  run → poll → disable → report) against the real gateway API end to end. The six scenario rows
  came back `FAILED` only because no issuer was reachable to complete any purchase - not a defect
  in this plan's code.
