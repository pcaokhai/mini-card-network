# MCN-405 Chaos Lab screen — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans with superpowers:test-driven-development. Worktree `../mcn-worktrees/web-405-chaos-lab`, branch `feat/MCN-405-chaos-lab`. Requires MCN-003 merged (MSW mocks generated from `contracts/openapi.yaml`) and MCN-004 (shell nav/`MockProvider`). Builds against `NEXT_PUBLIC_API_MOCKS=true` MSW handlers per the delivery plan's "frontend never waits for backend" rule — does not wait for MCN-404's real gateway implementation; switching to the real backend later is the existing `NEXT_PUBLIC_API_MOCKS=false` config flag, no code change.

**Goal:** A Chaos Lab screen shows six failure-scenario toggle cards with an active-count header, a money-verification panel that updates live during a run and flashes green/zero on success or red with the run id on a non-zero discrepancy, and a reaction panel listing what the system does for each active failure in both Easy and Expert text.

**Architecture:** `useChaosScenarios()`/`useSetChaosScenario()` and `useStartChaosRun()`/`useChaosRun(runId)` (new `src/shared/api/chaos-client.ts`, same `openapi-fetch` + `@tanstack/react-query` shape as `network-client.ts`/`overview-client.ts`) back a new `ChaosLabScreen` composed of `ScenarioCard`×6 (`src/components/chaos/ScenarioCard.tsx`), `MoneyVerificationPanel.tsx` (subscribes to WS `chaos.run.progress`/`chaos.changed` via the existing `useWsEvents` hook — same pattern `LiveFeed.tsx` already uses), and `ReactionPanel.tsx`. A run is started via `useStartChaosRun`'s mutation; its returned `runId` is then also used to filter the `useWsEvents(["chaos.run.progress", "chaos.changed"])` subscription so progress events for a *different* browser tab's run don't cross-pollute this screen.

**Tech Stack:** Next.js App Router, TypeScript strict, `@tanstack/react-query`, `openapi-fetch`, `next-intl`, existing `useWsEvents`.

**Spec:** `contracts/openapi.yaml` (`ChaosScenario`, `ChaosScenarioId`, `ChaosRun`), `contracts/ws-events.schema.json` (`chaos.changed`, `chaos.run.progress`), `docs/06-user-stories.md` MCN-405.

## Global Constraints

- No hardcoded palette/spacing — reuse the existing design tokens already used by `KpiCards`/`overview.css` (`rounded-lg border border-canvas`, etc.) rather than inventing new ones for this screen.
- Money values render through the existing `formatMoney` helper (`@/shared/format/money`), never hand-formatted.
- Both `en.json`/`vi.json` get every new `chaos.*` key added in the same PR (per root `CLAUDE.md`'s Definition of Done).
- `expertMode` follows the same prop convention `LiveFeed({ expertMode })` already established — Easy vs Expert text is a prop-driven render branch, not a second component tree.

## Ruling: chaos scenario id vocabulary shared with MCN-404

The six `ChaosScenarioId` string values (`SLOW_NETWORK`, `CONNECTION_CUT`, `DROP_RESPONSE`, `DUPLICATE_REQUEST`, `ISSUER_DOWN`, `LATE_RESPONSE`) come directly from `contracts/openapi.yaml`'s enum — this plan's MSW mock handlers and `ReactionPanel`'s per-scenario copy must use exactly these six ids as translation-message keys (`chaos.scenarios.SLOW_NETWORK.easyText` etc.), matching MCN-404's gateway-side `ChaosScenarioID` consts verbatim. Do not invent shorter or differently-cased ids.
