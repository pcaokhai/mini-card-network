**Goal:** `/cards` lists cards with status badges; a detail view shows a card visual, three-line balance (ledger/available/held), holds, limits with usage-bar sliders, and a ledger table; block/unblock requires inline confirmation with a lock-overlay animation and an audit-trail line; a limit change sends `If-Match` and a 412 shows "Someone changed this card. Reload to continue."

**Architecture:** `web-next/src/app/(console)/cards/{page.tsx,[cardRef]/page.tsx}` — `CardsListScreen.tsx` (`useQuery` on `GET /v1/cards`), `CardDetailScreen.tsx` (`useQuery` on `GET /v1/cards/{cardRef}` capturing the response `ETag` for the next mutation's `If-Match`), `CardVisual.tsx`, `BalanceLines.tsx`, `HoldsList.tsx`, `LimitsSliders.tsx` (usage-bar sliders, `useMutation` for `PUT .../limits` with `If-Match`), `LedgerTable.tsx`, `BlockConfirmDialog.tsx` (inline confirm, not a full modal takeover — matching AC2's "inline confirmation" wording), `AuditLine.tsx`.

**Tech Stack:** Next.js App Router, TanStack Query (capturing response headers via `openapi-fetch`'s raw `Response` for the `ETag`, since generated types don't carry headers — confirm the exact mechanism the generated client exposes for this before assuming), MSW, Vitest + Testing Library, Storybook, `next-intl`, Motion.

**Spec:** `contracts/openapi.yaml` (`CardSummary`/`CardDetail`/`CardLimits`/`JournalEntry`), `docs/04-api-contract.md` (`ETag`/`If-Match`, 412 `precondition-failed`), `docs/06-user-stories.md` MCN-309, `rules/web/design-quality.md`.

## Global Constraints

- The lock overlay animation on block/unblock uses `transform`/`opacity` only.
- A 412 response's user-facing message is exactly "Someone changed this card. Reload to continue." per AC3's literal wording — not a paraphrase.
- No raw PAN anywhere in this screen; `CardSummary.maskedPan` is the only PAN-shaped value ever rendered.

## Ruling: capturing `ETag` from a generated `openapi-fetch` response

`openapi-fetch`'s typed client normally returns `{ data, error }`, discarding raw headers. `GET /v1/cards/{cardRef}`'s `ETag` must be captured to send back as `If-Match`. Read the real generated client's actual call signature (`openapi-fetch` supports accessing the raw `Response` via its `response` field on the result, per its own documented API — confirm this against the actual installed version in `web-next/package.json` before assuming) and use whichever real mechanism exists; if the installed version genuinely has no way to access response headers through the typed wrapper, fall back to a raw `fetch` call for this one specific endpoint (still going through the same base URL/auth conventions as the generated client) rather than inventing a broader change to the client-generation setup — a single documented exception is simpler than modifying shared infrastructure for one header.
