# MCN-307 Transaction Journey screen — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans with superpowers:test-driven-development. Worktree `../mcn-worktrees/web-307-transaction-journey`, branch `feat/MCN-307-transaction-journey`. Requires MCN-004 merged. Does **not** wait for MCN-304 (GW, this same sprint's wave 2) — builds against MSW mocks from `contracts/openapi.yaml`'s `Journey` schema, per the established "frontend never waits for backend" pattern.

**Goal:** `/transactions/{rrn}` shows a summary header, a step timeline, per-step message detail, and a money panel; autoplay/step-back/step-forward/restart controls; the current step pulses, future steps are dimmed; opening a transaction from the feed (MCN-306), POS (MCN-305), or search navigates here.

**Architecture:** `web-next/src/app/(console)/transactions/[rrn]/` — `JourneyScreen.tsx` (container: `useQuery` for `GET /v1/transactions/{rrn}/journey`; local `useState` for the current playback step index, since playback position is per-view UI state, not server state), `SummaryHeader.tsx`, `StepTimeline.tsx` (the pulsing-current/dimmed-future visual — CSS `data-state` attributes, `transform`/`opacity` only), `StepDetail.tsx` (renders a `JourneyStep`'s `IsoMessage` fields, reusing MCN-104's `FieldTable`/`DetailPanel` components if their shape fits — check before duplicating), `MoneyPanel.tsx`, `PlaybackControls.tsx` (autoplay via `setInterval`, step back/forward/restart).

**Tech Stack:** Next.js App Router, TanStack Query, MSW, Vitest + Testing Library, Storybook, `next-intl`, Motion (`useMotionPreference`-gated pulse animation).

**Spec:** `contracts/openapi.yaml` (`Journey`/`JourneyStep`/`IsoMessage`/`Actor`/`StepKind`), `docs/06-user-stories.md` MCN-307, `rules/web/design-quality.md` (a step timeline is exactly the kind of "grid-breaking editorial" or "motion that clarifies flow" surface the anti-template policy asks for — this should feel like a real product feature, not a generic accordion).

## Global Constraints

- Autoplay interval should be slow enough to read (e.g. 2s per step, matching a "explain what happened" pacing, not a rapid technical replay) — pick a concrete default and make it configurable via a small control, not hardcode an arbitrary number without stating it.
- Pulsing/dimming animation uses `transform`/`opacity` only, gated by `prefers-reduced-motion` (falls back to a static current-step highlight with no animation).
- Reuse MCN-104's `FieldTable`/`DetailPanel` for rendering `IsoMessage.fields` if their existing props fit `IsoField`'s shape (they should, since both come from the same OpenAPI `IsoField` schema) — don't fork a second implementation of "render ISO fields as a table" if one already exists and fits.
