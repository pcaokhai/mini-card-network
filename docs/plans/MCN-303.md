# MCN-303 Purchase flow in the gateway — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans with superpowers:test-driven-development. Worktree `../mcn-worktrees/gw-303-purchase-flow`, branch `feat/MCN-303-purchase-flow`. Requires MCN-203 merged (`Mux`) and, for the contract, MCN-302a's real issuer response shapes (RC 91/14/62/etc., RC 96 placeholder) — but per the delivery plan this story only needs MCN-302's **contract** (already in `contracts/openapi.yaml`/ISO spec), not its merged code; build and test against an in-process fake issuer, same pattern as MCN-202/203, and treat the real issuer as an integration-checkpoint concern.

**Goal:** `POST /v1/transactions/purchases` builds a real 0200, sends it through the `Mux`, persists every state transition, maps the 0210 to a `Transaction` response, handles "link not signed on" without sending anything, and is idempotent on `Idempotency-Key`.

**Architecture:** `internal/purchase` owns a `Service.CreatePurchase(ctx, req, idempotencyKey) (Transaction, error)`: validates the request, checks `idempotency_record` for a replay, builds the 0200 (STAN via `Mux.NextSTAN()`, RRN computed per `docs/03` §5, DE 7/12/13/15 from wall-clock), inserts a `tran_log` row in `CREATED`, transitions to `SENT`, sends via `Supervisor`'s live `Mux` (reusing the connection exactly like MCN-204's manual triggers do — no second connection), maps the 0210 response to `APPROVED`/`DECLINED`, records the final state, and returns. Every transition is also written to `tran_state_history`. `internal/api/purchases.go` wires the REST handler; `internal/ws`'s hub (MCN-204) gets `BroadcastTransaction(event string, txn Transaction)`.

**Tech Stack:** Go 1.24, `pgx`, existing `internal/iso8583`/`internal/isonet` packages, `internal/store`, chi, `openapi-fetch`-compatible JSON.

**Spec:** `docs/03-iso8583-interface-spec.md` §5 (RRN, STAN, dedupe), §6 (processing codes), §7.2, `contracts/openapi.yaml` (`PurchaseRequest`/`Transaction`/`TransactionStatus`), `docs/05-data-model.md` (`acquirer.tran_log`, `tran_state_history`, `idempotency_record`), `docs/04-api-contract.md` (idempotency semantics), `docs/06-user-stories.md` MCN-303.

## Global Constraints

- Money stays `int64` minor units throughout; `Money{Amount int64, Currency string}` matches the OpenAPI `Money` schema exactly.
- Every REST write route requires `Idempotency-Key`; a replayed key with an identical request body returns the stored response unchanged (per `docs/04-api-contract.md`'s idempotency rule — read it before implementing to confirm the exact conflict-on-different-body behavior).
- `docs/03` §9: request timeout is 30s — `Mux.Send`'s `ctx` must carry exactly this deadline for a purchase.
- No PAN/PIN ever logged in clear — `CardPresentData.cardToken` (a simulator token, never a real PAN) is what crosses the wire in v1; there is no real PAN anywhere in the gateway for this story since MCN-305's simulator sends tokens, not PANs (confirm this reading of `CardPresentData`'s schema is correct before building DE 2 from it — see Task 2's check).

## Ruling: how a `cardToken` becomes DE 2 (PAN)

`contracts/openapi.yaml`'s `CardPresentData.cardToken` is described as "Simulator token for a test card from `contracts/fixtures/cards.json`; never a PAN." The gateway needs a real PAN to build DE 2, so it must resolve `cardToken → PAN` using `contracts/fixtures/cards.json` directly (the same fixture MCN-301 seeds the issuer from) — a small `internal/purchase/cardtokens.go` loads this fixture once at startup (embedded via `go:embed`, same technique MCN-202's `store.Migrate` used for embedding migrations) and maps `cardToken → {pan, expiryYymm}`. This keeps real PANs out of any request/response body or log (the token is what the browser and API ever see), while the gateway — which does need the real PAN momentarily to pack DE 2 — gets it from the shared fixture, not from the wire. This mirrors how a real POS's PAN entry never appears in application logs even though the acquirer's switch must have it to route the message.

package purchase

import (
	"fmt"
	"time"
)

// BuildRRN implements docs/03 §5: last digit of year + 3-digit day-of-year + 2-digit UTC hour + STAN.
func BuildRRN(now time.Time, stan string) string {
	yearDigit := now.Year() % 10
	dayOfYear := now.YearDay()
	return fmt.Sprintf("%d%03d%02d%s", yearDigit, dayOfYear, now.Hour(), stan)
}
