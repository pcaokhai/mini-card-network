# MCN-005-SET Settlement service skeleton — Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans with superpowers:test-driven-development (small story). Worktree `../mcn-worktrees/set-005`, branch `feat/MCN-005-set-skeleton`. Requires MCN-002 merged. Parallel with MCN-005-GW and MCN-005-ISS.

**Goal:** A Spring Boot `settlement` service on :8082 whose management port :9466 serves `/health/live`, `/health/ready` and `/prometheus`, with JSON logs (PAN masked, trace ids from the OpenTelemetry agent) and graceful shutdown within 30 s.

**Architecture:** Generated by Spring Initializr (latest Spring Boot, resolved at execution), hexagonal package skeleton, Actuator health groups mapped to `/health/live` and `/health/ready`, Logback with logstash-logback-encoder and the same masking decorator as the issuer, OpenTelemetry Java agent in the container.

**Tech stack:** Java 25, Spring Boot (web, actuator, Micrometer Prometheus), Gradle Kotlin DSL with dependency locking, logstash-logback-encoder, JUnit 5, AssertJ, ArchUnit, Spotless.

## Understanding

MCN-005 AC (docs/06 §E0); settlement rules in `settlement/CLAUDE.md`; ports docs/02 §8 (8082 API, 9466 management); `infra/prometheus/prometheus.yml` already scrapes `settlement:9466/prometheus`.

**Not executed in the planning sandbox** (no access to Spring Initializr or Maven Central there). Run every verification step.

## Rulings

- Health endpoints live on the management port (9466) with the Prometheus endpoint; the API port (8082) carries only business endpoints. Cost: probes must target 9466.
- The masking decorator and its test are copied from MCN-005-ISS (no shared library).
- AC3 verified with a `traceparent` sent directly to the service (same ruling as MCN-005-GW).

### Task 2: Health, metrics and graceful shutdown (AC1, AC4)

**Step 1 — failing test** `src/test/java/io/mcn/settlement/HealthEndpointsTest.java`

```java
package io.mcn.settlement;

import static org.assertj.core.api.Assertions.assertThat;

import org.junit.jupiter.api.Test;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.boot.test.context.SpringBootTest;
import org.springframework.web.client.RestClient;

@SpringBootTest(
    webEnvironment = SpringBootTest.WebEnvironment.RANDOM_PORT,
    properties = "management.server.port=0")
class HealthEndpointsTest {

  @Value("${local.management.port}")
  int managementPort;

  private String get(String path) {
    return RestClient.create("http://127.0.0.1:" + managementPort).get().uri(path).retrieve().body(String.class);
  }

  @Test
  void should_expose_live_and_ready_on_management_port__MCN_005_AC1() {
    assertThat(get("/health/live")).contains("\"status\":\"UP\"");
    assertThat(get("/health/ready")).contains("\"status\":\"UP\"");
  }

  @Test
  void should_expose_prometheus_metrics__MCN_005_AC1() {
    assertThat(get("/prometheus")).contains("jvm_memory");
  }
}
```

Run: `./gradlew test` → fails (404 on `/health/live`: default paths are `/actuator/health/...`).

**Step 2 — implement** `src/main/resources/application.yaml` (delete Initializr's `application.properties`)

```yaml
spring:
  application:
    name: settlement
  lifecycle:
    timeout-per-shutdown-phase: 30s
server:
  port: 8082
  shutdown: graceful
management:
  server:
    port: 9466
  endpoints:
    web:
      base-path: /
      exposure:
        include: health,prometheus
  endpoint:
    health:
      probes:
        enabled: true
      group:
        live:
          include: livenessState
        ready:
          include: readinessState
```

Run: `./gradlew test` → PASS. (Spring Boot sets readiness to `REFUSING_TRAFFIC` when graceful shutdown starts, which satisfies the draining requirement of AC4.) Commit: `feat(set): health groups, prometheus, graceful shutdown (MCN-005)`.

### Task 5: Container with OpenTelemetry agent (AC3)

`Dockerfile`

```dockerfile
FROM eclipse-temurin:21-jdk AS build
WORKDIR /src
COPY . .
RUN ./gradlew --no-daemon bootJar

FROM eclipse-temurin:21-jre
WORKDIR /app
ADD https://github.com/open-telemetry/opentelemetry-java-instrumentation/releases/latest/download/opentelemetry-javaagent.jar /otel/opentelemetry-javaagent.jar
COPY --from=build /src/build/libs/*-SNAPSHOT.jar /app/settlement.jar
EXPOSE 8082 9466
ENV JAVA_TOOL_OPTIONS="-javaagent:/otel/opentelemetry-javaagent.jar"
ENTRYPOINT ["java", "-jar", "/app/settlement.jar"]
```

Check: if the build produces both a plain and a boot jar, set `tasks.jar { enabled = false }` so the glob copies one file.

`compose.yaml`

```yaml
services:
  settlement:
    build: { context: ./settlement }
    environment:
      OTEL_SERVICE_NAME: settlement
      OTEL_EXPORTER_OTLP_ENDPOINT: ${OTEL_EXPORTER_OTLP_ENDPOINT}
      OTEL_EXPORTER_OTLP_PROTOCOL: grpc
      OTEL_METRICS_EXPORTER: none
      OTEL_LOGS_EXPORTER: none
    ports: ["8082:8082", "9466:9466"]
    stop_grace_period: 35s
    depends_on: [otel-collector, postgres, kafka]
```
