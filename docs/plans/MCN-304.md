# MCN-304 Transactions query and journey API — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:executing-plans with superpowers:test-driven-development. Worktree `../mcn-worktrees/gw-304-transactions-journey`, branch `feat/MCN-304-transactions-journey`. Requires MCN-303 merged (`TranLogRepository`, `purchase.Service`, `tran_state_history`).

**Goal:** `GET /v1/transactions` (filtered, cursor-paginated, newest first), `GET /v1/transactions/{rrn}`, and `GET /v1/transactions/{rrn}/journey` (ordered steps with actor/offset/easy-technical text/kind, masked ISO messages, and a money timeline) so the console can list and replay any transaction.

**Architecture:** `internal/store/tranlog.go` (MCN-303) gains `List(ctx, filter) ([]Transaction, nextCursor, error)` and `Get(ctx, rrn) (Transaction, error)`. A new `internal/journey` package builds a `Journey` from a transaction's `tran_state_history` rows plus its stored request/response ISO messages (already masked at capture time, per every prior story's PAN-masking discipline) — each state transition becomes one `JourneyStep` with a plain-language `easyText` (a small lookup table keyed by `(fromStatus, toStatus)` or by RC, e.g. "Card is blocked" for RC 62) and `technicalText` (the raw MTI/RC/field summary). The money timeline derives from the transaction's own amount and outcome (v1 has no DE 54 balance-reporting yet since that's issuer-side and not wired end to end — see Ruling).

**Tech Stack:** Go 1.24, `pgx`, chi, existing `internal/iso8583`/`internal/purchase` types.

**Spec:** `contracts/openapi.yaml` (`TransactionSummary`/`Transaction`/`Journey`/`JourneyStep`/`IsoMessage`), `docs/03-iso8583-interface-spec.md` §10 (trace correlation), `docs/05-data-model.md` (`tran_log`, `tran_state_history`), `docs/06-user-stories.md` MCN-304.

## Global Constraints

- Cursor pagination, newest-first, per the OpenAPI `items`/`nextCursor` envelope shape already established by MCN-204's `/v1/network/events` — reuse the exact same cursor-encoding convention (confirm from the real merged `network.go` what that convention actually is — an opaque base64 offset, a timestamp, etc. — before inventing a different one here).
- Every ISO message embedded in a `JourneyStep` is already masked (DE 2 first-6+stars+last-4, no DE 52/55 in clear) — this story reads already-stored, already-masked data; it does not re-implement masking.
- Money stays `int64` minor units in every response.

## Ruling: money timeline without real issuer DE 54 balance data

`Journey.money[].balanceAfter` is nullable in the OpenAPI schema precisely for this reason: v1's issuer (MCN-302b) doesn't report a post-transaction balance in DE 54 (that field is documented as "balance inquiry response" only, per `docs/03` §3's DE 54 note). This story's money timeline therefore has exactly one row per transaction — `{label: "Purchase", delta: -amount, balanceAfter: null, atStep: <the approval/decline step's seq>}` for a purchase — rather than a running balance ledger. This is a deliberate v1 scope limit, not a bug; a future story that wires DE 54 through would extend `JourneyBuilder` to populate `balanceAfter` for real, without changing this story's shape.

package journey

import (
	"testing"
	"time"

	"github.com/stretchr/testify/require"

	"github.com/mcn/gateway-go/internal/store"
)

func TestBuildJourney_approvedPurchaseHasPosAcquirerIssuerSteps__MCN_304_AC2(t *testing.T) {
	txn := store.TranLogRow{RRN: "x", Type: "PURCHASE", Status: "APPROVED", ResponseCode: "00", Amount: 10000, Currency: "704", CreatedAt: time.Now()}
	history := []store.StateTransition{
		{FromStatus: "CREATED", ToStatus: "SENT", At: txn.CreatedAt},
		{FromStatus: "SENT", ToStatus: "APPROVED", At: txn.CreatedAt.Add(50 * time.Millisecond)},
	}

	j := BuildJourney(txn, history)

	require.Len(t, j.Steps, 2)
	require.Equal(t, "POS", string(j.Steps[0].Actor))
	require.Equal(t, "ISSUER", string(j.Steps[1].Actor))
	require.Contains(t, j.Steps[1].EasyText, "Approved")
	require.Len(t, j.Money, 1)
	require.Equal(t, int64(-10000), j.Money[0].Delta)
}

func TestBuildJourney_declinedBlockedCardHasEasyText__MCN_304_AC2(t *testing.T) {
	txn := store.TranLogRow{RRN: "y", Type: "PURCHASE", Status: "DECLINED", ResponseCode: "62", Amount: 5000, Currency: "704", CreatedAt: time.Now()}
	history := []store.StateTransition{{FromStatus: "SENT", ToStatus: "DECLINED", At: txn.CreatedAt}}

	j := BuildJourney(txn, history)

	require.Contains(t, j.Steps[0].EasyText, "blocked")
	require.Equal(t, "BAD", string(j.Steps[0].Kind))
}
