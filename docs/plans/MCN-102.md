# MCN-102 jPOS packager and vector tests — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans with superpowers:test-driven-development. Worktree `../mcn-worktrees/iss-102-packager`, branch `feat/MCN-102-jpos-packager`. Requires MCN-003 merged (`contracts/iso8583/packager-spec.yaml` and vectors already exist) and MCN-005-ISS merged (Gradle project, ArchUnit, logging exist).

**Goal:** `src/dist/cfg/iso87ascii.xml`, a jPOS `GenericPackager` XML descriptor, generated from the same `contracts/iso8583/packager-spec.yaml` that MCN-101 generates the Go codec from — so both hosts parse byte-identical wire format by construction, not by coincidence. Every golden vector pack/unpacks byte-identical through the generated packager. The issuer's log formatter masks PAN and other sensitive DEs.

**Architecture:** A Gradle task (`generatePackager`) reads `packager-spec.yaml` (via SnakeYAML, already a jPOS transitive dependency) and writes `iso87ascii.xml` in jPOS's `GenericPackager` schema, one `<isofield>` per DE with the matching `ISOFieldPackager` implementation class (`IFA_LLCHAR`/`IFA_LLLCHAR`/`IFA_FIXED`/`IFB_BINARY`/…). A small `PanMaskingLogFormatter` wraps jPOS's own message logging to mask sensitive DEs before they reach `logback.xml`'s JSON pipeline (MCN-005-ISS already wired PAN masking for free-text log lines; this task additionally masks the *ISOMsg dump* jPOS itself writes when packager/channel logging is on).

**Tech Stack:** Java 25, Gradle Kotlin DSL (custom task type), jPOS 3.0.1's `GenericPackager`/`ISOMsg`, SnakeYAML (transitive via jPOS), JUnit 5, AssertJ.

**Spec:** `docs/03-iso8583-interface-spec.md` §2–3, `contracts/iso8583/packager-spec.yaml`, `contracts/iso8583/vectors/*.json`, `docs/06-user-stories.md` MCN-102, `issuer-jpos/CLAUDE.md` (layout: `src/dist/cfg/iso87ascii.xml`).

## Rulings

- jPOS's `GenericPackager` XML format and its exact `ISOFieldPackager` class names for `n`/`an`/`ans`/`b` with `LL`/`LLL`/fixed lengths must be confirmed against the resolved jPOS 3.0.1 jar (`org.jpos:jpos:3.0.1`, already locked in MCN-005-ISS's `gradle.lockfile`) before writing the generator — read `org/jpos/iso/packager/GenericPackager.class`'s expected DTD/schema and the `org.jpos.iso.IFA_*`/`IFB_*` class list via `unzip -l` on the resolved jar, rather than guessing from older jPOS docs (the same class of version-drift risk that hit MCN-005-ISS's Javalin/logstash-logback-encoder assumptions).
- DE 1 (secondary bitmap) is **not** listed as an explicit `<isofield>` in `GenericPackager` XML — jPOS's `ISOBasePackager` derives and packs/unpacks the secondary bitmap automatically from which DEs ≥ 65 are present, the same way MCN-101's Go codec and MCN-003's Python reference do it manually. Confirm this against the resolved jPOS behavior in Task 2 rather than assuming; if jPOS 3.0.1 requires an explicit DE 1 entry, add it and record the ruling.
- Masking targets exactly the DEs `docs/03` §3 marks `sensitive`: PAN (2), key material (48), PIN block (52), ICC/EMV data (55) — the story text says "DE 2, 35, 45, 52, 55" but `packager-spec.yaml` has no DE 35/45 (those are track-2/track-1 fields, explicitly out of scope for v1 per `docs/03` §2 "Track 2 `z` — Not used in v1"); mask what the spec actually defines as sensitive (2, 48, 52, 55) and note this correction in the PR description rather than silently following the stale story text.

```kotlin
// buildSrc/src/main/kotlin/GeneratePackagerTask.kt
import org.gradle.api.DefaultTask
import org.gradle.api.tasks.Input
import org.gradle.api.tasks.InputFile
import org.gradle.api.tasks.OutputFile
import org.gradle.api.tasks.TaskAction
import org.yaml.snakeyaml.Yaml
import java.io.File

abstract class GeneratePackagerTask : DefaultTask() {
    @get:InputFile
    abstract val specFile: org.gradle.api.file.RegularFileProperty

    @get:OutputFile
    abstract val outputFile: org.gradle.api.file.RegularFileProperty

    @TaskAction
    fun generate() {
        @Suppress("UNCHECKED_CAST")
        val spec = Yaml().load<Map<String, Any>>(specFile.get().asFile.reader())
        @Suppress("UNCHECKED_CAST")
        val fields = spec["fields"] as Map<Int, Map<String, Any>>

        val xml = StringBuilder()
        xml.append("<!-- Code generated from contracts/iso8583/packager-spec.yaml by :generatePackager. DO NOT EDIT. -->\n")
        xml.append("<isopackager>\n")
        for ((number, f) in fields.toSortedMap()) {
            val type = f["type"] as String
            val length = f["length"] as Int
            val prefix = f["prefix"] as String?
            val name = f["name"] as String
            val packagerClass = fieldPackagerClass(type, prefix)
            xml.append("  <isofield id=\"$number\" length=\"$length\" name=\"${escape(name)}\" class=\"$packagerClass\"/>\n")
        }
        xml.append("</isopackager>\n")
        outputFile.get().asFile.writeText(xml.toString())
    }

    private fun fieldPackagerClass(type: String, prefix: String?): String = when {
        type == "n" && prefix == "LL" -> "org.jpos.iso.IFA_LLNUM"
        type == "n" && prefix == "LLL" -> "org.jpos.iso.IFA_LLLNUM"
        type == "n" -> "org.jpos.iso.IFA_NUMERIC"
        type == "an" -> "org.jpos.iso.IFA_ALPHA"
        type == "ans" && prefix == "LLL" -> "org.jpos.iso.IFA_LLLCHAR"
        type == "ans" -> "org.jpos.iso.IFA_LLCHAR"
        type == "b" && prefix == "LLL" -> "org.jpos.iso.IFB_LLLBINARY"
        type == "b" -> "org.jpos.iso.IFB_BINARY"
        else -> error("unhandled type=$type prefix=$prefix")
    }

    private fun escape(s: String) = s.replace("&", "&amp;").replace("\"", "&quot;")
}
```

Note: `fieldPackagerClass`'s branches must exactly match the DE 41/42 `ans` *fixed*-length case too (no prefix, right-space-padded) — `packager-spec.yaml` has no `ans` fixed entries with a prefix of `""` mapping to `IFA_LLCHAR` above incorrectly; **fix this before running**: add a fourth `ans`-without-prefix branch using the fixed alphanumeric class found in Task 1 (commonly `org.jpos.iso.IFA_LLCHAR` is LL-prefixed by name despite the "LL" in the class name sometimes being used generically in older jPOS — verify the *actual* fixed-length ans class name in Task 1's jar inspection and use it here, not `IFA_LLCHAR`).

package io.mcn.issuer.adapter.iso;

import static org.assertj.core.api.Assertions.assertThat;

import com.fasterxml.jackson.databind.JsonNode;
import com.fasterxml.jackson.databind.ObjectMapper;
import java.io.File;
import java.nio.file.Files;
import java.util.Iterator;
import java.util.Map;
import java.util.TreeMap;
import org.jpos.iso.ISOMsg;
import org.jpos.iso.packager.GenericPackager;
import org.junit.jupiter.api.Test;
import org.junit.jupiter.params.ParameterizedTest;
import org.junit.jupiter.params.provider.MethodSource;

class PackagerVectorTest {

  private static GenericPackager packager() throws Exception {
    return new GenericPackager("src/dist/cfg/iso87ascii.xml");
  }

  static java.util.stream.Stream<File> vectors() throws Exception {
    return Files.list(new File("../contracts/iso8583/vectors").toPath())
        .map(java.nio.file.Path::toFile)
        .filter(f -> f.getName().endsWith(".json"));
  }

  @ParameterizedTest
  @MethodSource("vectors")
  void should_pack_and_unpack_byte_identical__MCN_102_AC2(File file) throws Exception {
    ObjectMapper mapper = new ObjectMapper();
    JsonNode vector = mapper.readTree(file);
    String mti = vector.get("mti").asText();
    String expectedPacked = vector.get("packed").asText();

    ISOMsg msg = new ISOMsg();
    msg.setPackager(packager());
    msg.setMTI(mti);
    Iterator<Map.Entry<String, JsonNode>> it = vector.get("fields").fields();
    while (it.hasNext()) {
      Map.Entry<String, JsonNode> e = it.next();
      msg.set(Integer.parseInt(e.getKey()), e.getValue().asText());
    }
    String packed = new String(msg.pack());
    assertThat(packed).as("pack " + file.getName()).isEqualTo(expectedPacked);

    ISOMsg unpacked = new ISOMsg();
    unpacked.setPackager(packager());
    unpacked.unpack(expectedPacked.getBytes());
    assertThat(unpacked.getMTI()).isEqualTo(mti);
    var expectedFields = new TreeMap<Integer, String>();
    vector.get("fields").fields().forEachRemaining(e -> expectedFields.put(Integer.parseInt(e.getKey()), e.getValue().asText()));
    for (var entry : expectedFields.entrySet()) {
      assertThat(unpacked.getString(entry.getKey())).as("DE " + entry.getKey()).isEqualTo(entry.getValue());
    }
  }
}
```

package io.mcn.issuer.adapter.logging;

import org.jpos.iso.ISOMsg;

/** Formats an ISOMsg for logging with PAN masked and other sensitive DEs redacted (docs/02 §7.6, docs/03 §3). */
public final class IsoLogMasker {
  // DE -> label from packager-spec.yaml's `sensitive:` tag, for fields that are not PAN-shaped
  // digit runs and so cannot use PanMasker's regex (key material, PIN block, EMV TLV).
  private static final java.util.Map<Integer, String> REDACT_ONLY = java.util.Map.of(48, "key-material", 52, "pin-block", 55, "emv");

  private IsoLogMasker() {}

  public static String maskedDump(ISOMsg msg) {
    StringBuilder sb = new StringBuilder("MTI=").append(msg.getMTI());
    for (int i = 2; i <= 128; i++) {
      if (!msg.hasField(i)) continue;
      String value = msg.getString(i);
      sb.append(' ').append(i).append(": ");
      if (REDACT_ONLY.containsKey(i)) {
        sb.append("[MASKED ").append(REDACT_ONLY.get(i)).append(']');
      } else if (i == 2) {
        sb.append(PanMasker.mask(value));
      } else {
        sb.append(value);
      }
    }
    return sb.toString();
  }
}
```
